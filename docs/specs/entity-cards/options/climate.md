# Card Options — Climate

Part of the [common contract](./common.md), which defines the universal options (`name`, `icon`, `hideName`, `hideState`, `color`, `tapAction`, `holdAction`, `doubleTapAction`) and the action model; those are not repeated here. **Status: the option surface below is implemented; this document is reconciled by change [0017](../../../changes/0017-climate-card-to-spec.md) PR 3**, which closes its open questions and flips the entity-cards restatement. `src/components/ClimateCard/` renders both variants, gates every option below on what the entity advertises, and edits them through the shared configuration form; the MUST-keep behaviors in [Preserved behavior](#preserved-behavior) are unchanged. **Tier layouts below are implemented**: change [0011](../../../changes/0011-layout-tiers.md) PR 3 built `glance`, `row` and `tall` with two temporary deviations, and change [0017](../../../changes/0017-climate-card-to-spec.md) has since resolved both — `full` renders the compact layout with the arc dial behind `variant: dial` (PR 1, with the pinning migration convention 7 requires), and `glance` is control-free now that the dialog controls below are registered (PR 2, in the same PR that dropped the stepper).

Applies to entities in the `climate` domain (thermostats, heat pumps, AC units, TRVs).

## Primary action

`tapAction: default` for a climate card MUST mean **open more-info** (the entity detail dialog), not toggle.

Rationale: unlike a light or switch, the climate card body is dense with embedded controls — the +/- stepper, mode pills, preset pills — which already consume their taps (per the [common contract](./common.md#action-type), actions never fire from embedded controls). The residual tappable surface is small and sits between live controls, so a tap-to-toggle default would make accidental HVAC shutdowns one mis-tap away, and "toggle" is itself ill-defined for a thermostat (off ↔ which of `heat`/`cool`/`heat_cool`/`auto`?). Turning the system off/on is an explicit act via the `off` mode pill or the detail dialog. Users who want a toggle-like tap MAY still configure `tapAction: call-service` (e.g. `climate.turn_off`) deliberately.

- **GIVEN** a climate card with defaults
- **WHEN** the user taps the card background (not a stepper, pill, or the dial)
- **THEN** the entity detail dialog opens and no `climate.*` service is called.

## Options

All keys live under `item.config`, are camelCase, and follow the [common conventions](./common.md#conventions-for-per-card-options) — in particular rule 3: whether a control _can_ appear is derived from the entity's `supported_features` and attributes; the `show*` options below only hide or tune what the entity supports, never enable what it does not.

| Key               | Type                                        | Default   | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | ------------------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `variant`         | select: `dial` \| `compact`                 | `compact` | Presentation of the temperature control. `compact` is the stepper/pills presentation described in [Tier layouts](#tier-layouts); `dial` is the existing arc thermostat (drag-on-arc setpoint). `dial` renders only in the `full` tier — in smaller tiers a `dial` card MUST fall back to the `compact` layout for that tier.                                                                                                                                                                                                     |
| `showModePills`   | boolean                                     | `true`    | Renders the HVAC mode pill row built from the entity's `hvac_modes`. `full` tier only.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `showPresets`     | boolean                                     | `false`   | Renders preset pills (e.g. eco/comfort/away) from `preset_modes`; only offered/rendered when the entity supports presets (`SUPPORT_PRESET_MODE`, bit 16, and a non-empty `preset_modes`). `full` tier only.                                                                                                                                                                                                                                                                                                                      |
| `showFanModes`    | boolean                                     | `false`   | Renders fan-mode pills from `fan_modes`; only offered/rendered when the entity supports fan modes (`SUPPORT_FAN_MODE`, bit 8, and a non-empty `fan_modes`). `full` tier only.                                                                                                                                                                                                                                                                                                                                                    |
| `showCurrentTemp` | boolean                                     | `true`    | Appends "currently X°" (from `current_temperature`) to the state line in `row`/`tall`/`full`. In `glance` the single state slot always shows the **target** (the setpoint is the card's headline) and this option is omitted — degrade by omission, not composition.                                                                                                                                                                                                                                                             |
| `showHumidity`    | boolean                                     | `true`    | Shows current humidity ("· 45%", muted, `--liebe-c-water` accent for the droplet glyph) in the `full` tier state area; only offered/rendered when `current_humidity` is present on the entity.                                                                                                                                                                                                                                                                                                                                   |
| `displayUnit`     | select: `auto` \| `celsius` \| `fahrenheit` | `auto`    | Display conversion only. Climate entities carry no per-entity `temperature_unit` attribute — HA normalizes climate values to `hass.config.unit_system.temperature`, which is the native unit here. `auto` shows that unit; the other values convert every displayed temperature (target, range, current). Service calls MUST always send values in the unit-system native unit — the stepper steps and clamps natively and only the rendering converts. Fixtures MUST model the unit system, never a synthetic entity attribute. |

Prose notes:

- **`variant`.** `compact` is the default because the arc dial only earns its space at `full` size, while `compact` degrades cleanly through every tier; defaults must look right with zero configuration at any size. The `dial` variant MUST resolve through the same card-dispatch path as every other registered variant rather than a switch private to the climate card, consistent with the weather family — the concrete registry API is change [0017](../../../changes/0017-climate-card-to-spec.md)'s to choose. Changing `variant` MUST NOT change behavior — both variants call the same services with the same step/clamp rules.
- **`showModePills` and state colors.** Mode pills MUST use the [domain color discipline](../../design-system/index.md#domain-color-discipline): the selected pill takes the active tint pattern in its mode color — `heat` → `--liebe-c-heat` (orange), `cool` → `--liebe-c-cool` (sky), `heat_cool`/`auto` → `--liebe-c-ok` (green), `off` → neutral gray; `dry` and `fan_only` SHOULD use `--liebe-c-water` (cyan) and neutral respectively. The icon circle and state text MUST take the same mode color regardless of `showModePills`, resolved totally over `hvac_action` values: **active actions override the mode** — `heating`/`preheating`/`defrosting` → heat (orange), `cooling` → cool (sky), `drying` → water (cyan), `fan` → neutral — while `idle`, `off`, an absent attribute, or any unrecognized action **fall back to the entity-state mode mapping above** (an idle thermostat shows its mode's color at the inactive treatment). Entity state `unknown`/`unavailable` resolves with highest priority to the **neutral gray** treatment (the common shell's unavailable rendering) with every control inert — stale `hvac_action`/attributes never color the card or leave steppers/pills active. Every valid HA climate state resolves deterministically to exactly one token.
- **`showPresets` / `showFanModes` default `false`.** Presets and fan modes are secondary controls most thermostats users touch rarely; on by default they crowd the `full` tier. They are opt-in tuning of an already capability-gated control (rule 3 both ways: the option cannot conjure pills the entity lacks, and the entity cannot force pills the user hid).
- **`showCurrentTemp`.** The state line composes as `<hvac state> · currently 21.5°` (state colored per mode, the "currently" fragment muted). With `showCurrentTemp: false` only the HVAC state renders. `hideState: true` (common) suppresses the whole line and wins.
- **`displayUnit`.** Mirrors the weather card's `temperatureUnit` semantics but under the select-forward key naming (rule 5); conversion is presentation-only so a Fahrenheit display over a Celsius entity still sends `{ temperature: 21.5 }`, never `{ temperature: 70.7 }`.

## Preserved behavior

These are already implemented and MUST hold for every variant, tier, and option combination:

- Setpoint changes MUST step by `target_temp_step` (default 0.5) and clamp to `[min_temp, max_temp]`; the decrease stepper MUST be disabled at `min_temp` and the increase stepper at `max_temp` (bound-disabled steppers).
- When the entity supports `SUPPORT_TARGET_TEMPERATURE_RANGE` (bit 2) and is in `heat_cool`, the card MUST present dual setpoints (`target_temp_low` / `target_temp_high`), send `{ target_temp_low, target_temp_high }` via `climate.set_temperature`, and MUST reject inverted ranges (`low >= high`). In range mode the low setpoint carries the heat color and the high setpoint the cool color.
- Mode changes go through `climate.set_hvac_mode`; presets through `climate.set_preset_mode`; fan modes through `climate.set_fan_mode`.
- All controls are hidden in edit mode (selection semantics per [entity-cards](../index.md)).

## Tier layouts

Tiers per the [design-system size-adaptive layouts](../../design-system/index.md#size-adaptive-layouts). Content that does not fit MUST be omitted, never clipped.

| Tier           | Content                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `glance` (1×1) | Icon circle in the HVAC state color (active tint pattern; heating = orange, cooling = sky, off = neutral), name, and the **target temperature** as the state value in the state color — setpoint display and controls are gated **per control family, not globally**: scalar setpoint display and every scalar stepper/dial are gated on `TARGET_TEMPERATURE` (bit 1), while the dual low/high range controls are gated on `TARGET_TEMPERATURE_RANGE` (bit 2). A range-only entity (bit 2 without bit 1 — legitimate for heat_cool-only thermostats) MUST therefore still render its dual setpoints; gating everything on bit 1 would leave it with no temperature control at all. With neither bit the state slot shows `current_temperature` (or the HVAC state when that too is absent) and no setpoint UI renders. No controls; the whole tile is the primary action (more-info by default). In range mode the state shows `low–high`. |
| `row` (≥2×1)   | Glance content laid out as icon + meta row, plus the **+/- stepper** with the target temperature as a large numeric readout (`liebe-value`, tabular-nums) between the buttons. Range mode shows two compact steppers (low / high) when width ≥3; at width 2 the range readout gets a single stepper pair that shifts **both setpoints in lockstep** (± one `target_temp_step` each, preserving the band width, clamped so neither setpoint leaves `[min_temp, max_temp]`) — deterministic in every `hvac_action` including `idle`, and matching the "make it warmer/cooler" intent of a compact control. Independent low/high adjustment is available at width ≥3 and in `full`.                                                                                                                                                                                                                                                           |
| `tall` (1×≥2)  | Icon on top, target temperature readout and a **vertical stepper** (+ above, − below) center, meta at bottom.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `full` (≥2×≥2) | Row layout plus secondary controls in order: **mode pills** (`showModePills`), **preset pills** (`showPresets`), **fan-mode pills** (`showFanModes`), and the state area gains **current humidity** (`showHumidity`). With `variant: dial`, the stepper/readout region is replaced by the arc thermostat (which embeds its own +/- and drag handles); pills and humidity render below the dial under the same options.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

- Every option row above states its tier gating; options whose tier never renders (e.g. `showPresets` on a 2×1 card) are simply inert, not invalid — resizing the card later activates them.
- **The control-free `glance` is what ships.** It depends on the detail dialog exposing the thermostat's setpoint control, so the two landed together (change [0017](../../../changes/0017-climate-card-to-spec.md) PR 2): dropping the stepper first would have left a 1×1 thermostat with **no way to change the setpoint at all**, which the no-operability-regression invariant forbids at a merge point. The dialog mounts the card's own stepper and mode row rather than a copy of them.
- **`full` renders the compact layout, with the dial behind `variant: dial`.** Moving the dial there replaced an existing control surface, so change 0017 PR 1 shipped it with the pinning migration convention 7 requires: every climate card placed before that build carries `variant: 'dial'` and renders exactly what it did before.

## Scenarios

### Scenario: Compact stepper respects step and clamp

- **GIVEN** a `heat`-mode thermostat at `temperature: 34.5` with `target_temp_step: 0.5` and `max_temp: 35`, rendered as `variant: compact` in `row` tier
- **WHEN** the user taps the increase stepper
- **THEN** the card calls `climate.set_temperature` with `{ temperature: 35 }` and the increase stepper becomes disabled.

### Scenario: Dial variant falls back below full tier

- **GIVEN** a climate card with `config.variant = 'dial'` on a 2×2 span showing the arc thermostat
- **WHEN** the user resizes it to 2×1 in edit mode
- **THEN** the card re-renders in the `row` compact layout (icon, meta, stepper) with identical service behavior, and restores the dial when resized back to ≥2×≥2.

### Scenario: Fahrenheit display keeps native service units

- **GIVEN** a thermostat on a Celsius unit system (`hass.config.unit_system.temperature: '°C'`, `temperature: 21`, `target_temp_step: 0.5`) with `config.displayUnit = 'fahrenheit'`
- **WHEN** the card renders and the user taps increase
- **THEN** the readout shows `69.8°F` before and `70.7°F` after (21°C = 69.8°F, 21.5°C = 70.7°F, one-decimal display precision), and the service call is `climate.set_temperature` with `{ temperature: 21.5 }` (native units).

### Scenario: Preset pills are capability-gated and opt-in

- **GIVEN** a `full`-tier climate card with `config.showPresets = true` on an entity whose `supported_features` lacks `SUPPORT_PRESET_MODE`
- **WHEN** the card renders
- **THEN** no preset pill row appears; when the same config is applied to an entity advertising **both** `SUPPORT_PRESET_MODE` (bit 16) and `preset_modes: ['eco', 'comfort']`, the pills render and tapping "eco" calls `climate.set_preset_mode` with `{ preset_mode: 'eco' }`.

## Open Questions

- **Humidity control vs display.** `showHumidity` is display-only; entities with `SUPPORT_TARGET_HUMIDITY` (bit 4) could get a target-humidity control in `full` tier, but no option is specified for it yet.
- **Swing mode and aux heat.** `swing_modes` (bit 32) and `aux_heat` (bit 64) are read by the current attribute type but have no control or option surface; whether they belong on the card or only in more-info is open.
- **Dial in `tall` tier.** Whether a vertically-cropped arc (semi-dial) is worth specifying for `variant: dial` at 1×≥2, or the compact fallback is final, is open.
- ~~**`hvac_action` vs state coloring precedence.**~~ Resolved: the total, action-first mapping in the `showModePills` note above is normative (active actions override the mode; `idle`/`off`/absent/unrecognized fall back to the mode mapping) and change 0017 restates it. Multi-stage heat-pump verification belongs to that change's tests, not to a pending decision — no longer open. It previously read: confirmation against real multi-stage heat-pump entities before implementation.
- ~~**Rounding rule for converted display.**~~ Resolved (change 0017): converted displays round to **one decimal** — the Fahrenheit scenario encodes it (`69.8°F`/`70.7°F`) and integer rounding would lose step visibility. Previously open: whether to display one decimal or round to integers needed a decision shared with the weather card.
