# 0019 — Cover & Fan Cards to Spec

## Summary

Implement the domain-specific options from the [cover](../specs/entity-cards/options/cover.md) and [fan](../specs/entity-cards/options/fan.md) option contracts on top of the tier layouts (0011) and universal option surface (0014). Cover gains `showPositionSlider`, `showButtons`, `showTiltControls`, `invertPosition` (reversed-scale mapping at the entity boundary), `deviceClassIcon`, the `stateLabels` position display style, and — for security device classes — the `confirmOpen` gate on every opening-increasing route; fan gains `speedControl` (`slider` | `steps` | `none`, steps derived from `percentage_step` — with **legacy pinning** per common convention 7: existing fan items keep their step-style speed control via a loader migration writing `speedControl: 'steps'`, since the slider default replaces how existing cards are operated; only new cards default to `slider`; `showOscillate` and other newly introduced controls are additive and need no pinning), `showPresets`, `showOscillate`, `showDirection`, `animateIcon` (reduced-motion-safe spin), and `showPercentage` — plus config-form entries and tier placements for both. One change, two cards: they share the motor-control shape (a position/speed slider on the 0010 anatomy, horizontal and vertical) but land as separate PRs. Universal options and the action system are already in place per 0014 and are not re-implemented here.

**Spec:** [entity-cards](../specs/entity-cards/index.md) → [options/cover](../specs/entity-cards/options/cover.md), [options/fan](../specs/entity-cards/options/fan.md) · **Status:** draft · **Depends on:** 0011, 0014

## Motivation

`CoverCard` ships open/stop/close with position-based disabling, an optimistic-drag position slider, and tilt controls — all capability-gated but with zero configuration surface; `FanCard` ships toggle, a hardcoded quartile speed control, and a preset select, likewise unconfigurable. Both option docs are fully specified and everything they need underneath (slider anatomy from 0010, tiers from 0011, universal options and config plumbing from 0014) has landed. This change also resolves the entity-cards spec's open question about `CoverCard`'s contradictory `minHeight` styling (component sets 160/180/200px, tests assert 60/80/100px): the 0011 tier layouts supersede fixed per-card minHeights, so the override and its stale assertions get cleaned up here.

## Requirements

### Testing Requirements

Per [architecture — Testing & Quality Conventions](../specs/architecture/index.md#testing--quality-conventions):

- `npm test`, `npm run lint`, `npm run typecheck` MUST pass; `codecov/patch` 100%; `codecov/project` no regress.
- Every option MUST ship stories demonstrating its values ([storybook — story coverage](../specs/storybook/index.md#story-coverage)): cover slider/buttons/tilt per tier, both `stateLabels` styles, `invertPosition` and `deviceClassIcon` both values; fan `speedControl` all three styles per tier, presets/oscillate/direction, `animateIcon` and `showPercentage` both values.
- Service payloads MUST be unit-tested (`cover.set_cover_position` / `set_cover_tilt_position` / open-stop-close / tilt open-close; `fan.set_percentage` / `set_preset_mode` / `oscillate` / `set_direction`; 0%-slider-commit → `fan.turn_off`), and feature gating MUST be unit-tested against the `supported_features` bit matrices for both domains (an option can never enable an unsupported capability).
- `invertPosition` MUST have tests proving the boundary conversion is symmetric and consistent: display shows the effective position, `cover.set_cover_position` payloads are converted back into the entity's reversed scale (effective `100` → `{ position: 0 }`), position-derived disabling follows the effective position, state strings are never remapped, and tilt is unaffected.
- Fan step derivation (`percentage_step` → pill values, quartile fallback, nearest-pill selection) MUST be unit-tested as a pure function; `animateIcon` MUST have a test showing the spin is suppressed under `prefers-reduced-motion: reduce` regardless of the option.
- Removal of the `CoverCard` fixed `minHeight` MUST update the existing contradictory assertions rather than delete coverage.

Skipping or weakening any rule to land the PR is a bug in the PR.

### Functional requirements

The [cover](../specs/entity-cards/options/cover.md) and [fan](../specs/entity-cards/options/fan.md) option docs own the option keys, defaults, tier placements, primary-action matrices, capability gating, and control behavior — including their scenarios, which are this change's acceptance criteria and are not restated here. What implementing them requires of this change:

- Options are stored under `item.config` and edited via each card's `CardConfig` form alongside the shared 0014 fragment, round-tripping through YAML. Both cards' baseline "MUST NOT expose a configuration modal" is retired.
- **All cover movement commands** (toggle, open/stop/close, position and tilt commits) and all fan commands migrate to the non-retrying dispatch path from [0014](./0014-universal-card-options.md) — a retried motor command reverses or repeats physical movement — each holding its guard from dispatch until the expected state transition or an acknowledgement timeout, not merely promise resolution.
- `CoverCard`'s fixed `minHeight` override (160/180/200px) is removed; the 0011 tier layouts govern sizing. This closes the entity-cards spec's size-discrepancy open question and updates the contradictory 60/80/100 assertions rather than deleting that coverage.
- Both cards register their primary controls in the detail dialog's domain control slot from [0014](./0014-universal-card-options.md), so covers stay operable at tiers where the button row does not render and fan speed stays adjustable at `glance` or under `speedControl: none`.
- `invertPosition` is implemented once at the entity boundary as a symmetric conversion pair rather than per call site — see Design Decisions.

## Design Decisions

- **One change, two PRs** — cover and fan share the motor-card shape (capability-bit gating, an optimistic-drag percentage slider horizontal and vertical, `full`-tier auxiliary controls), so specifying them together keeps the shared conventions aligned; but each card lands in its own PR per the one-feature-per-PR rule, so a review issue on tilt never blocks fan presets.
- **Tier layouts supersede fixed minHeights** — resolves the entity-cards open question ("CoverCard size styling discrepancy"): the 160/180/200px component override predates 0011 and contradicts both its own tests and the tier system. The tier layouts are the sizing contract; the override and the stale 60/80/100 assertions are replaced together, not papered over.
- **`invertPosition` is a symmetric boundary mapping, in exactly one place** — a pure effective↔raw conversion pair (`effective = 100 − raw` on read; `raw = 100 − effectiveTarget` on commit) used by readout, slider, state line, and position-derived disabling, per the option doc. It is NOT display-only: commits are converted into the entity's reversed scale so the device drives to what the user sees (effective 100 → `{ position: 0 }`). The config form states the consistently-reversed-integration scope. Tests pin the wire payloads so a future refactor cannot quietly flip semantics.
- **Step derivation is a pure helper** — `percentage_step` → pill values (with the quartile fallback and nearest-pill matching, preserving the shipped bucketing tolerance) lives in one unit-tested function in the FanCard component folder, keeping arithmetic out of JSX. It derives the speed count from `percentage_step` and evenly divides, so every step value yields integer pills ending at 100; refining their labeling against real hardware stays an open question in the option doc.
- **Spin is decorative CSS, never a state signal** — `animateIcon` maps percentage to an animation duration on the existing glyph; the reduced-motion gate is a media query in the stylesheet, so it holds even if component logic regresses. On/off remains fully conveyed by tint and text with the animation suppressed.
- **Device-class icon mapping is data** — a single `device_class` → open/closed glyph table beside the CoverCard, with the generic pair as the fallback row; the universal `icon` override short-circuits it entirely, so the precedence rule lives in one lookup.

- Open questions deferred in the option docs: `invertTilt` (note: neither `unknown`/`unavailable` covers nor tilt-only covers are deferred — the former resolve inert and the latter resolve `more-info`, per the option doc's total primary-action matrix, both in PR 1's action tests), slider behavior while a cover is moving, fan `turnOnPercentage`, and the `row`-tier preset-vs-speed precedence select.
